## Design Questions (brainstorm later)

- **Concept doc reading experience:** "Open this file" is dead on arrival for terminal-first students. Options to explore: (1) coach renders the key points inline in the chat, (2) `open` command launches it in the default app, (3) replace concept docs with a visual or short video, (4) concept doc content gets woven into the module steps rather than siloed as separate files.
- **Use the agents-vs-workflows HTML deck as the teaching model:** github.com/aistudycamp/course-materials/blob/main/decks/agents-vs-workflows.html — built together with Ben, covers chatbot vs workflow vs agent at the right level of granularity. This is what conceptual teaching should look like in this course. Consider serving it directly via `open` command or embedding it in the frontend.
- **Stage 2 workflow design (decided):** Drop file → AI classifies meeting type → routes to one of 3 folders → sends notification. Has: event trigger, AI decision, branching logic, persistent output, notification. This is what makes it clearly different from Stage 1. Google Drive integration may be too complex for the sprint — local folder watch with Slack/email notification may be the right scope. Needs scoping decision.
- **File opening UX across the whole course:** Can we auto-open files for students? `open -a "Visual Studio Code" <path>` works if they have VSCode. Need a decision at the start of the course (or in stage-1-intro) about which editor they're using — then every "open this file" becomes a real command. Needs to be established once, not repeated.
